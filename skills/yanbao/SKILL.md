# A股深度研报

以独立、审慎的卖方研究员视角完成研究。严格执行本 Skill 规定的完整度标准：可以扩展，任何适用模块不得删除、合并后漏项或只保留标题。

**团队署名**：韩小洋同学使用AI生成。

**禁止使用 Agent Teams 或子代理。** 全流程由当前代理完成。

## 开始前必须读取

1. 读取 [report-blueprint.md](references/report-blueprint.md)，按固定章节和最低交付物搭建报告骨架。
2. 读取 [financial-analysis.md](references/financial-analysis.md)，完成三表、勾稽、业绩归因和财务质量分析。
3. 读取 [risk-screening.md](references/risk-screening.md)，逐项执行财务排雷和前瞻信号核查。
4. 读取 [valuation-scenarios.md](references/valuation-scenarios.md)，完成估值、情景和敏感性测算。
5. 写作完成后读取 [quality-gates.md](references/quality-gates.md)，执行覆盖、数字、证据和时效审计。
6. 对重资产、多业务、技术制造或处于资本开支周期的公司，读取 [core-engine-and-heavy-asset-method.md](references/core-engine-and-heavy-asset-method.md)，识别核心经营引擎并完成资本开支到盈利兑现的闭环分析。

不得因数据缺失跳过章节。无法取得数据时，保留该项并写明：`数据暂缺（已核查：来源A、来源B；截至YYYY-MM-DD），不据此下结论`。

## 1. 锁定对象与口径

先确认：公司全名、六位代码、交易所、主营业务一句话、产业链、公司类型、报告基准日、最新定期报告期。公司类型至少在周期资源、制造成长、消费、科技硬件、软件服务中选一类；混合型公司可选主类型加辅类型。

所有“当前、最新、近期”均以执行当日为准。行情、估值、股东、公告、预测、价格和供需数据必须标注具体截止日；不得沿用其他公司或历史任务中的事实与日期。

## 2. 数据获取与准备（保持此路径）

### 2.1 来源优先级

| 数据 | 第一优先级 | 第二优先级 | 最后手段 |
|---|---|---|---|
| 财务三表、附注、治理、分红 | 当前公司目录 `02_转换资料` 中公告/年报/半年报/季报 Markdown；优先最新并补齐历史 | `a-stock-data` 补缺或核对 | WebSearch 查公司官网、交易所、巨潮等官方原文 |
| 行情、估值、股东、资金和市场数据 | `a-stock-data` | 官方披露或权威行情页 | WebSearch，并注明口径与时间 |
| 公司公告、业绩预告、投资者关系 | `a-stock-data` 公告功能 | 公司官网/交易所/巨潮原文 | WebSearch 定位原文 |
| 行业、产业链、政策、贸易和价格 | WebSearch，优先协会、政府、统计机构、海关、公司公告和权威价格机构 | `a-stock-data` 研报/行业数据 | 券商或媒体；不得以搜索摘要代替正文 |
| 竞争对手财务 | 对手的 `02_转换资料` | `a-stock-data` 批量查询 | 对手官网/交易所财报原文 |

严格先查前一来源；只有缺失、时段不足或口径不明才降级。不得把本地分析脚本或中间产物当成新的数据源。不得直接读取 PDF 代替已有的逐份转换 Markdown。

### 2.2 最低数据范围

- 财务：至少近5个完整年度加最新季度/半年；若本地资料支持更多年份，优先使用8-10年以覆盖完整周期。
- 行业：近5年历史供需与未来3-5年预测；周期公司复盘至少3个代表性周期，若行业历史不足则覆盖全部可得周期。
- 治理：十大流通股东使用离报告日最近一期且列全10名；展示持股数、占比、环比变化方向和数量。股东变化至少看近4季。
- 公告与新闻：重要公告至少近3个月，重要新闻至少近30日；重大项目、处罚、诉讼、减持和再融资按分析需要回溯3-5年。
- 一致预期：优先3-5家、至少2家可核验机构，列报告日期、评级、未来3年EPS/净利和目标价；识别离群预测。

### 2.3 研究台账

在草稿区建立四张台账：

1. **事实台账**：字段、原始值、单位、报告期、来源、页/章节或URL、获取日、实际/预测。
2. **冲突台账**：原始值A、原始值B、差异原因、采信值、采信理由。
3. **假设台账**：价格、销量、产能利用率、利润率、税率、估值倍数等假设及依据。
4. **缺口台账**：未取得字段、已查来源、对结论的影响、报告内披露位置。

## 3. 数字与证据规则

### 3.1 单位换算

- 先去除千位分隔符，再按原单位转目标单位；计算与展示单位必须分开记录。
- 万元转亿元除以10,000；元转亿元除以100,000,000；万股转亿股除以10,000。
- 示例：`35,107万股 = 3.5107亿股`；`852,802,345元 = 8.5280亿元 ≈ 8.53亿元`。
- 中间过程至少保留4位小数，最终通常保留2位；反向还原原值并设置合理舍入误差。
- 市值、PE、PS和每股指标的分子分母必须同单位、同股本口径、同报告期。

### 3.2 交叉验证

对营收、归母净利、EPS、股本、持股比例、产能/产量、投资收益、供需、市场价格、盈利预测和目标价逐项核验。优先级为：

`最新公司公告/定期报告 > 交易所/监管披露 > 官方统计/行业协会 > 可核验一致预期/券商原文 > 权威媒体 > 自媒体测算`。

原则上关键结论使用两个独立来源，其中至少一个是一手来源。只有单一来源时明确写“单一来源，待核实”。发生冲突时不得取更乐观值；先检查合并/母公司、扣非/归母、设计/有效产能、期末/平均股本、含税/不含税和实际/预测等口径。

用物理上限和财务勾稽反推：`产能 × 利用率 × 单价`、`被投企业净利 × 持股比例`、`目标市值 ÷ 预测净利`、`资产 = 负债 + 权益`。明显突破上限的成长性数字必须下修或标为不可采信。

## 4. 分析顺序

1. 搭建 [report-blueprint.md](references/report-blueprint.md) 的完整空骨架。
2. 先研究产业链、竞争格局、供需、成本、价格与政策，判断公司处于行业何处。
3. 再研究公司业务、基地、产能、客户、定价、护城河和治理。
3.1 对重资产、多业务或技术制造公司，先按 [core-engine-and-heavy-asset-method.md](references/core-engine-and-heavy-asset-method.md) 写出一句话核心经营引擎、唯一关键变量和业务主次排序，再展开分部细节。
4. 按 [financial-analysis.md](references/financial-analysis.md) 分析三表，区分年度和单季数据，完成量价、利润桥和杜邦。
5. 按 [risk-screening.md](references/risk-screening.md) 做排雷；红灯必须进入摘要和风险章节，黄灯进入跟踪指标。
6. 形成未来3年分部盈利预测，再按 [valuation-scenarios.md](references/valuation-scenarios.md) 做至少两种估值、三情景和核心变量敏感性。
7. 最后写摘要、结论、操作区间、风险、催化剂和跟踪指标；摘要必须与正文测算一致。

## 5. 写作和输出

- 文件名：`{产业链}及{公司名}深度研究报告_AI生成_{YYYYMMDD}.md`
- 保存：`./03_研究产物/`，目录不存在则创建。
- 完整研报原则上不少于8,000个中文字符；内容复杂时自然扩展，不以凑字数替代分析。只有用户明确要求简报时才可缩短，但仍保留全部适用模块并用精简表述。
- 对比型、时间序列和情景数据使用 Markdown 表格；解释、归因和判断使用正文。不要把长段落硬塞进表格。
- 每节以结论开头或结尾，回答“所以什么”；每个乐观判断同时给出失效条件或反证。
- 对事实、估计、预测和推断做清晰区分。预测表头使用 `E`，季度不得与全年直接横比或年化后冒充实际值。
- 每个关键数据就近标注来源和截止日；末尾附资料来源、关键数据核对区、假设与口径说明、重要声明。
- 禁止虚构来源、数值、机构观点、图表或缺失字段；禁止把其他公司或历史任务的数据迁移到当前公司。

- 所有价格、行情、预测、股东和催化剂标注日期；关键数字可追溯；
- 已执行 [quality-gates.md](references/quality-gates.md)，没有静默漏项、单位错误、未来数据伪装成实际或结论与正文矛盾。

- 对适用公司，已完成核心经营引擎、护城河证伪、技术产业化、分部—法人—基地穿透、资本开支兑现、季度边际和认知修正分析。

若任何一项未完成，不得声称“完整研报已完成”；应继续补齐或在报告中明确披露限制。
